# 共同工作规则

## 首次定位与资产边界

先完整读取PROHIBITIONS.md。告诉用户：Agent包绝对路径、源码根目录、固定需求资产绝对路径。无资产路径时询问这一必要信息；普通归档无需额外许可。不得默选本包data、桌面临时区、源码docs等路径。

配置/记录/历史/索引/周总汇全部写到独立资产。包仅含规则、脚本、模板、静态示例；运行时不向包写配置、staging或生成文件。使用python -B避免工具产生包内字节码。升级包只改变工具，继续指向同一资产。

## 每次需求

1. 运行info，核实选中固定资产；读取登记与相关需求记录。配置不存在则初始化，已存在不得再次init。
2. 取消息实际时间，优先平台时间，其次用户明确时间，最后系统接收时间；北京时间。无需保存原话，不生成聊天输入文件，不用原话哈希作为追溯。
3. 从对话理解需求，按可独立验收的目标拆分，保留实质条件但用整理后的表述。项目名/别名/功能与代码证据支持归属；不确定的项待归属，明确项继续。识别新建/补充/冲突/重复；补充保持稳定ID。
4. 仅只读查看相关源码和版本。Git证据与需求关联；远程不可查就注明，不能把本地缓存当最新远程。代码和部署状态分别看待。
5. 填标准章节及状态：需求状态和实施进度分开。新增默认未开始但明确“初始化，非代码核查”；历史项状态不明用待核实。进行中/阻塞/待验证均属未完成，具体情况写进度说明。
6. 用户说已经做完时可记录已完成，但必须记录“用户报告、未独立验证”的完成依据摘要。只读证据足够时记录证据来源；禁止为了确认进度跑业务测试、修改代码或部署。确认需求、提交代码都不自动等于完成。
7. 用stdin把整理后的JSON交给apply。输出白名单不允许raw_input/original_text字段。修订读取最新版，用expected_revision；不直接手改正式Markdown或历史。
8. 自动重建需求总览、项目索引、跨项目和项目内每周总汇。周表包含本周新增/更新/完成以及历史遗留，状态用蓝/橙/绿标记。检查遗漏条件、归属、状态依据与validate。
9. 简短回报固定资产目录、需求编号、周总汇路径与待澄清项。不回显长原话。

## 追溯与排序

稳定需求ID、消息时间、整理时间、规范化变更原因、状态依据、代码证据、版本历史足够用于追溯；不保存逐字原话。一个消息拆多需求用同一EV时间事件关联。变更记录不得将原话粘回reason/progress_note/evidence。

需求状态：待澄清/待确认/已确认/暂缓/已撤回/已合并。实施进度：未开始/未完成/已完成/待核实。建议P0-P3与用户确认分开；未明确影响不武断P0。改变优先级后未经再次确认应标未确认。

跨项目需求保持各项目职责，各自文档间用真实ID关联。归属纠正保留旧项，新建正确项目条目，旧项已合并并互相关联，不移动旧目录或删历史。v2只记录进度，不执行任务。
