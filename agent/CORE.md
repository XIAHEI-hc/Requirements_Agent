# 共同工作规则

## 首次定位

先完整读取 PROHIBITIONS.md。报告工具包绝对路径、源码根目录、固定需求资产绝对路径。缺失资产路径时询问，普通归档无需额外许可。配置、需求、修订、证据、总览、周总汇都只写独立资产。包和业务源码保持只读，使用 python -B 避免包内字节码。

运行 info 核实选中的长期资产。已有资产不能再 init；v2 先按迁移说明预览、迁入独立空资产、validate 后切换。未来工具升级继续使用同一份 v3 资产。

## 每次需求

1. 只在当前上下文理解自然语言。获取平台消息时间、用户明确时间或系统接收时间，按北京时间登记。禁止落盘原话、原话哈希或输入副本。
2. 识别独立需求、已有需求补充、状态反馈、重复与冲突。项目名、别名、功能和代码支持归属；不确定的项用 unassigned，显示“无明确项目”。项目仅为字段，不能创建项目归档目录。
3. 大型需求保留一项顶层需求，拆 children 子需求，各自带标题、验收标准和稳定编号。并列独立目标建顶层条目；拆分不能漏条件。跨项目独立需求用已有真实 ID 关联。
4. 只读查看相关源码和版本。按 req-source 获取证据；远程不可查明确未知，Git 与部署状态分开。严禁为了核实进度执行代码、业务测试、构建或部署。
5. 填标准章节和整理后的变更原因。新增默认 ⚪ 未开始，明确这是登记初始化。状态使用五种色标；用户反馈进行中、阻塞、解决或取消时，显式填写 progress_source 和 progress_note。已解决还需 completion_evidence 报告摘要或只读引用，不从确认、提交或制包推断完成。
6. 新增默认 requirement_date 取消息日期，archive_week 取该日期的周一。用户指定未来日期或归档周时明确设置这两个字段；created_at 和 updated_at 是工具实际建档/更新时刻，不伪造为未来日期。跨月工作周放在周一所在月，周末默认归前一个周一至周五。目录按 docs/02_目录时间与追溯.md。
7. 通过 apply --stdin 提交整理后的 JSON。新增生成 YYYYMMDD-NN 全局日序号；修订读取最新记录，用 id 和 expected_revision。普通修订保留 ID、日期、归档周和文件路径，标题改变也不移动文件。纠正项目归属在原条目修订并记录依据；不适用的旧源码证据从当前记录移除，历史保留。
8. children 修订列表须包含所有既有子项，带原子编号；未修改字段保留。新增子项不带 id，工具分配父ID-SNN。不能删除子项，需要撤销时标已取消并给依据。父项/子项状态不自动互推：父项已解决前，每个有效子项都必须有明确已解决记录。整体完成反馈明确覆盖子项时，逐项记录依据再更新父项。
9. apply 自动刷新本周需求总汇、总览、项目归属索引、每周总汇索引。原归档周显示最新状态；发生在别周的后续修订写入对应周“跨周补充与推进”，不算该周新需求。状态统计的五个状态数只统计顶层，子项另计，不重复相加。
10. 运行 validate；核对条件、项目、状态依据与周统计。简短回报固定资产目录、需求 ID、需求路径和周总汇路径；不回显长原话。

## 追溯与优先级

稳定 ID、事件时间、规范化原因、状态依据、只读代码证据和不可覆盖的修订足够追溯。禁止把原话贴进 reason、章节、证据或日志。

P0-P3 是建议，未知待评估（表中显示未设置）；确认优先级须有确认摘要，改优先级未再次确认就撤销确认标志。旧版 status 的需求确认枚举保留作内部兼容；主进度字段 progress 是五种状态，前台表格只显示它。v3 输入可用 status 表示五种状态，不能与 progress 冲突。需求确认不等于解决。

没有任务调度器或开发执行器；总汇在工具调用后更新，不声称自动完成业务任务。
