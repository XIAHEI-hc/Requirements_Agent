# 需求管理 Agent v3.0

自由表达需求，AI 只读理解项目，形成可追溯的 Markdown 并登记进度。**严禁业务代码改造；不保存用户原话；真实资产与工具包分离。**

## 这一版

- 目录采用 `09月/09.07-09.11/09.09-01-标题.md`，同目录为 `本周需求总汇.md`。工作周为周一至周五，不再建立项目/日期归档目录。
- 周总汇按样例提供状态统计、完整需求表、大型需求与子需求进度、跨周补充与推进。项目仅为表格归属字段。
- 使用 `⚪ 未开始`、`🟡 进行中`、`🔴 已阻塞`、`🟢 已解决`、`⚫ 已取消`。彩色图标兼容常见 Markdown 阅读器，不依赖 HTML 文字颜色。
- 原归档周持续显示最新进展；旧需求在本周推进只记跨周，不算本周新增。支持明确指定归档周、提前建档、父子需求及单独验收依据。
- 新需求编号为 `YYYYMMDD-NN`，同日跨项目统一递增；旧资产迁移保留已有稳定 ID 与 v2 全部修订。

## 开始

Python 3.10+，仅标准库；Git 证据查询需要 Git。无需安装依赖、服务或前端。

1. 从仓库获取工具包到独立工具目录。
2. 将 START_HERE_给AI的启动指令.md 交给有真实文件工具的 AI，并告诉它真实源码根目录与固定资产绝对路径。
3. AI 先说明三类路径，再初始化或读取长期资产。自然说需求即可，无需手写 JSON。
4. 从资产根目录 `需求总览.md`、`每周总汇索引.md`、`项目归属索引.md` 或对应工作周的 `本周需求总汇.md` 查看。

| 类型 | Windows 示例 | Linux 示例 |
| --- | --- | --- |
| 工具包和 Skills | D:/Tools/Requirements_Agent | /data/tools/requirements-agent |
| 业务源码（只读） | D:/Projects | /data/projects |
| 长期需求资产 | D:/Assets/Requirements | /data/assets/requirements |

可用已挂载的独立服务器/NAS 目录。本包不自动连接云服务，不默认向包内 data、源码 docs 或当前目录写产物。首个归档年份直接使用 月/周；其他年份加 YYYY年 外层避免覆盖，详情见 docs/02_目录时间与追溯.md。

**已有 v2 资产：先读 docs/05_v1迁移与包升级.md。**迁移到独立空目标资产，预览、校验后切换固定路径；不要直接对旧目录 init 或覆盖。业务源码不参与迁移。Skills 随仓库携带，不自动安装到个人目录。

验证：`python -B -m unittest discover -s tests -v`。演示：`python -B examples/demo.py`（临时模拟资产，不触及真实项目）。
