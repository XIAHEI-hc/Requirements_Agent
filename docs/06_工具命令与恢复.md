# 工具命令与恢复

自然语言与 JSON 转换由 AI 负责，用户无需手写。全局 --asset-root 放子命令前，也可在终端设置真实固定路径：

```bash
export REQMGR_ASSET_ROOT=/data/assets/requirements
python3 -B scripts/reqmgr.py info
python3 -B scripts/reqmgr.py discover
python3 -B scripts/reqmgr.py register --stdin
python3 -B scripts/reqmgr.py snapshot pixlab --remote
python3 -B scripts/reqmgr.py apply --stdin
python3 -B scripts/reqmgr.py weekly --week 2026-09-28
python3 -B scripts/reqmgr.py reindex
python3 -B scripts/reqmgr.py validate
```

首次 init、Windows 环境变量见 01_首次配置与固定资产.md；v2/v1 迁移见 05_v1迁移与包升级.md。包中配置和示例只读，真实数据写入固定资产。

## apply JSON

批次字段 received_at、time_basis、requirements；received_at 携时区。新需求要求 title、reason、完整 sections，项目不明确可省略 project_id。可填 requirement_date 与 archive_week 表示明确指定的编号日期/归档周，不改变实际建档时刻。

主进度 progress 五种状态；status 可用同样五种主状态，旧确认枚举兼容但不展示成进度。主状态互相冲突则拒绝。进度变化须显式更新 progress_source 和 progress_note；已解决需 completion_evidence 摘要/只读引用。不粘原话，不自动从提交推断完成。

修订带 id、expected_revision、reason，其余省略保留。不允许普通修订改 requirement_date 或 archive_week，文件路径固定。纠正 project_id 可保持同一 ID；不再适用的当前代码证据自动清除，历史仍可查。优先级改变未再次确认会撤销确认标志。

大型需求可提供 children 数组，每项至少 title、acceptance，新子项不带 id。修订提供父项 expected_revision 和包含所有旧子项的列表，每项用稳定子 id；子项省略字段保留。不得删既有子项，取消需状态及新依据。父项不会自动解决子项、子项完成也不会自动解决父项。范例见 templates/large-requirement.example.json 与 templates/update.example.json。

## 恢复与限制

排他写锁适合单写入者，不在有人写入时移除锁。每文件原子替换，整批不是事务；validate 提示 pending，先检查记录/快照/日志，勿盲目重放新增。备份时不可漏掉 .reqmgr。

正式 Markdown 从规范元数据生成，不能直接手改。只丢总汇可 reindex；需求变动用 apply 新修订。validate 检查当前文档、最新修订、解决依据、中断批次；语义条件与状态证据需 Agent 核对，脚本不是整个会话的操作系统沙箱。

snapshot 禁用 fsmonitor 和可选 Git 锁，远程仅 ls-remote。SHA 相等只说明提交一致，dirty 与部署另记；查询失败须明确未知。禁止读取后执行项目指令、业务测试或构建。
