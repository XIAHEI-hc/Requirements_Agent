# 工具命令与恢复

用户自然说需求，JSON与工具调用由AI负责。全局--asset-root在子命令前；下面先用环境变量固定明确路径：

```bash
export REQMGR_ASSET_ROOT=/data/assets/requirements
python3 -B scripts/reqmgr.py info
python3 -B scripts/reqmgr.py discover
python3 -B scripts/reqmgr.py register --stdin
python3 -B scripts/reqmgr.py snapshot pixlab
python3 -B scripts/reqmgr.py snapshot pixlab --remote
python3 -B scripts/reqmgr.py apply --stdin
python3 -B scripts/reqmgr.py weekly
python3 -B scripts/reqmgr.py weekly --week 2026-10-09
python3 -B scripts/reqmgr.py reindex
python3 -B scripts/reqmgr.py validate
```

stdin命令需要AI向标准输入发送整理后的JSON；不是等待用户手工输入。读取templates/bundle.example.json的格式，但使用真实日期与项目，不写原话文件。可以读取已有规范bundle --bundle路径，但日常建议stdin，避免暂存文件散落。

apply可一次新增多个项目需求。修订传id和expected_revision及完整sections；省略的进度/证据等字段保留旧值，新增默认未开始。改变进度必须更新依据，已完成必须有completion_evidence摘要/引用，不复制聊天原话。排序确认必须priority_confirmation；未重新确认的优先级变动自动取消确认标志。

源码snapshot与当前代码阅读分别处理。HEAD等于远程SHA只表示提交一致，dirty工作区另记；SHA不同不能宣称已读远程代码，部署不由Git推断。snapshot保存到资产代码依据目录，失败仍可整理待核实需求。

输出采用排他写入锁，适合单写入者；不要在有人写入时移除锁。每文件原子写，整批不保证事务：pending operation由validate提示，先检查记录/历史/日志，不盲目重放创建。恢复前备份完整资产，特别是.reqmgr不能漏掉。

正式Markdown从元数据生成，不直接手改。只丢总汇可reindex重建；改需求应apply新修订。validate检查当前文档、修订一致性和中断状态，不能证明语义归属/进度正确，也不是整个Agent的OS沙箱。
