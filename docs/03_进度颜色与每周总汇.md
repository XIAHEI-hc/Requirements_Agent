# 进度、颜色与每周总汇

| 实施进度 | Markdown标记 | 含义 |
|---|---|---|
| 未开始 | <span style="color:#2563eb">🔵 未开始</span> | 尚未启动或新需求初始化，注明依据 |
| 未完成 | <span style="color:#d97706">🟠 未完成</span> | 进行中、阻塞、待验证等尚未完成情况 |
| 已完成 | <span style="color:#15803d">🟢 已完成</span> | 用户明确报告或只读证据支持完成 |
| 待核实 | <span style="color:#64748b">⚪ 待核实</span> | 历史状态未知或依据不足 |

文件同时使用彩色圆点、明确文字和HTML span文字颜色。Markdown本身无统一颜色语法；阅读器可能禁用HTML样式，此时文字颜色不保证，但彩色图标和状态文字仍提供区分。静态例子见examples/周总汇示例.md。

需求确认状态和实施进度独立。“已确认+未开始”合法。已完成需要progress_source/progress_note/completion_evidence，用户报告也可以，但注明未独立验证；本Agent不得运行代码获取验证。未知进度不靠猜测填完成率。

周总汇同时生成跨项目与单项目文件，有本周新增/更新/完成、历史遗留、按项目各进度计数、完整需求表和待归属/待澄清。表内记录需求状态、进度标记、优先级和状态依据。旧周未完成会进入新周，哪怕本周没新需求。

统计口径：新增按首次提出日期；更新按实际记录的修订时间，包含新增；遗留是周前提出且截点尚未完成的有效项；完成按进度转入已完成计数，单纯改标题/优先级不再计完成。多个集合可能重叠，总表按ID去重。撤回/合并项不进入遗留池。

当前周截至现在，历史周截至周日末。历史表链接打开需求当前详情，当时进度以表内截点为准。晚录入的历史需求明确无法重建历史。周表可重建，不覆盖需求历史。

每次apply自动更新已涉及周和当前周；明确生成指定周：

```bash
python3 -B scripts/reqmgr.py --asset-root /data/assets/requirements weekly --week 2026-10-09
```

week可为周内任意日期。不安装定时任务；用户要求周回顾或AI归档时执行。若用户希望固定周五定时，需要以后在实际环境另行配置，不能假称已自动调度。
