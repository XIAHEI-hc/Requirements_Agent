# v1迁移与包升级

## 迁移当前需求

v2是新工具包，不覆盖v1。先选择独立的新资产目录，init并登记v1使用的项目ID，再执行：

```bash
python3 -B scripts/reqmgr.py --asset-root /data/assets/requirements-v2 migrate-v1 --v1-data /旧工具包/data
python3 -B scripts/reqmgr.py --asset-root /data/assets/requirements-v2 validate
```

迁移工具只读取v1 records和引用的源码证据JSON；不读取、不复制原始输入正文，不复制intakes或原话哈希，也不修改/删除v1任何文件。

保留需求ID、首次时间、当前需求内容、关系和优先级。在v2创建初始修订，并注明旧版revision及updated_at；旧版修订历史留在旧资产中，**不会自动导入全部旧历史**。v1没有实施进度字段，全部初始标待核实，不从已确认等状态推断完成。再由用户报告或只读证据更新。

目标须已初始化且无需求，新旧目录必须分离，项目ID需登记匹配。迁移后检查总览/周表，确认内容可用再自行决定旧包和旧原话如何保留或清理。本工具不会替你删除旧原话。

## 后续升级

新包解压到新工具目录，继续使用同一个固定资产--asset-root。包内没有真实数据，无需把越来越长的月周目录复制到新包。资产配置在资产本身，info确认路径和asset_id，防止误建第二套。

若只是换工具包，无需迁移资产。若真正换资产磁盘/挂载路径，先备份完整资产、迁移目录并由维护者显式更新.reqmgr/config.json的asset_root和相关源码路径；脚本拒绝静默接受改变的固定路径。
