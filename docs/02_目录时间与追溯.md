# 目录、工作周与追溯

固定资产根目录包含三个索引与管理元数据；可读需求严格采用月份／工作周／单个文件。以首次初始化年份 2026 为例：

```text
固定需求资产/
├── 需求总览.md
├── 项目归属索引.md
├── 每周总汇索引.md
├── 09月/
│   ├── 09.07-09.11/
│   │   ├── 本周需求总汇.md
│   │   └── 09.09-01-本地AI需求按工作周管理.md
│   └── 09.28-10.02/
│       ├── 本周需求总汇.md
│       └── 09.28-01-示例需求.md
├── 2027年/（其他年份防重名；首次年份不加这一层）
│   └── 09月/...
├── 修订历史/需求ID/r0001.md
├── 代码依据/SRC-....json
└── .reqmgr/（配置、记录、修订、操作日志）
```

不建项目目录，不建日期子目录。项目归属显示在需求与周表；项目归属索引用表格分组并按优先级排序。

## 日期规则

- 工作周显示周一至周五，`09.28-10.02` 放 `09月`，月份与年份以周一为准。
- 周六/周日默认归此前工作周，文件仍用真实需求日期，例如 `10.10-01-标题.md` 放 `10.05-10.09`。有明确指定时按 archive_week。
- 时区固定北京时间。received_at 为消息事件时间；requirement_date 是标题/编号/文件日期，默认消息日期；archive_week 是归档周周一，可明确指定；created_at、updated_at 为工具实际创建/更新时间。
- 可提前建档：9 月 28 日创建、用户指定 requirement_date=2026-10-09 与 archive_week=2026-10-05，则创建时间仍为 9 月 28 日，编号为 20261009-01，仅统计在 10.05-10.09 周。
- archive_year 在初始化时固定，等于初始化年份。这个年份直接 月/周；别的年份放 YYYY年/月/周，避免多年重名，不随系统时间改变。

## 编号与历史

新增 ID `YYYYMMDD-NN`，文件名 `MM.DD-NN-标题.md`，同一天跨项目统一递增，编号不复用。标题清洗文件系统禁用字符、括号及空白，保证相对链接可打开。旧资产导入保留旧 ID，文件名使用按日期分配的序号。子项 ID 为 父ID-S01、S02 等，不新增目录；需求详情和周总汇同时展示子项。

普通修订保持 ID、日期、归档周和路径不变，改标题也不重命名原文件，避免旧链接失效。项目纠正在原 ID 修订，不移动文件；旧证据、旧归属可查修订历史。

每次修订保存规范化 JSON 与 Markdown 快照，旧版次禁止覆盖。原周总汇显示最新记录；跨周日志保留每次后续修订的时刻、状态、原因与原需求链接，不把今天的状态伪称为历史当时状态。无原话档案。
